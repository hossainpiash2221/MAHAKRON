1. PROJECT AT A GLANCE
---------------------
This is a customer-facing fashion e-commerce storefront for MAHAKRON, built with Next.js App Router, React 19 and Tailwind CSS. Customers browse products, choose available color/size variants, add items to a browser-persisted cart, submit a cash-on-delivery order, and view order history saved in that browser.

The intended server/data flow is:
Browser pages/components -> this Next.js server (/api/* and server rendering) -> Google Apps Script web app -> Google Sheet / existing order manager -> delivery workflow.
A Telegram bot notification can report failed orders. The browser should call this site's endpoints only; Apps Script credentials must remain server-side.

Important behavior:
- Product data is read through Apps Script and cached server-side (fresh about 2 minutes; a last good copy may be served stale for up to 24 hours). Browser provider also retains product data per visit/session and refreshes after 5 minutes.
- Product prices and order totals provided by the browser are not authoritative. Quote/order requests send item identifiers, quantities and variants; Apps Script should validate against the sheet and compute final values.
- Cart and local order history live in localStorage, not a customer account or central order-history API. “My Orders” is therefore browser/device-specific.
- Delivery display/rates are configured in src/lib/delivery.js; the Next order route forwards the selected rate configuration to Apps Script. Keep the Apps Script side consistent when changing delivery behavior.
- Product catalog is external (Google Sheet). Do not assume product records are stored in this repo.

3. ROUTES AND CUSTOMER JOURNEY
------------------------------
/                  Home: hero, categories, featured products, male product slider and ordering steps.
/products          Browse/filter/search product catalog.
/products/[slug]   Product details; variant selection and add to cart.
/cart              Review cart items and quantities.
/checkout          Enter customer details and delivery area; obtains a quote and submits order.
/my-orders         View orders stored in this browser's local storage.
/api/products      Read product catalog from server-side cached Apps Script data.
/api/quote         Ask the backend for a current quote based on item IDs/qty/variants.
/api/order         Validate and submit a cash-on-delivery order.
/api/telegram/order-failed  Send a failed-order notice to configured Telegram destination.
/robots.txt, /sitemap.xml  SEO metadata routes.

Typical data flow: RootLayout calls getProducts() -> ProductsProvider shares catalog -> product UI adds item keyed by productId + color + size -> CartProvider persists it -> checkout POSTs /api/quote and /api/order -> Next server calls Apps Script -> result is recorded in OrdersProvider local history. Failed order notification may call the Telegram route.

4. CONFIGURATION AND SECRETS
----------------------------
.env.local exists locally but MUST NOT be pasted into another AI, committed, or included with this guide. Variable names and purpose:
- APPS_SCRIPT_URL: private Apps Script deployment URL (server only).
- API_SECRET: shared secret between this Next server and Apps Script (server only).
- NEXT_PUBLIC_SITE_URL: public canonical website base URL.
- NEXT_PUBLIC_STORE_NAME: public store display name.
- TELEGRAM_BOT_TOKEN: private Telegram bot token (server only).
- TELEGRAM_CHAT_ID: destination for failed-order notifications (server only).
Never prefix secrets with NEXT_PUBLIC_. Use a separate secret channel/config manager when deploying. README describes Apps Script Script Properties including API_SECRET and ADMIN_TOKEN; that backend deployment is not present in this checkout.

6. ENGINEERING RULES FOR A FUTURE AI EDITOR
------------------------------------------
1) First inspect the relevant file and its imports/callers. Follow existing patterns and keep changes scoped.
2) Keep Apps Script URL, API_SECRET, Telegram token and other credentials server-only. Never put secret data in client components, logs, documentation or responses.
3) Treat client cart/product data as untrusted. Validate and whitelist on the server; Apps Script/sheet is authoritative for products, stock, variants and price.
4) Keep API response shapes compatible with current callers (usually { success, data } or { success: false, error }). Preserve rate limiting, request validation, timeout and failure behavior when editing endpoints.
5) Cart line identity includes productId + color + size. Do not merge distinct variants.
6) Order history is localStorage-based. A change to “my orders” should account for browser/device limits or intentionally migrate the architecture.
7) Product descriptions may contain formatted content. Use existing sanitization helpers; do not render arbitrary HTML unsafely.
8) Product records live in an external Sheet and Apps Script. If changing backend contracts or delivery rules, check/update both sides. This checkout currently lacks apps-script source, so identify that limitation before editing backend-only behavior.
9) Avoid editing package-lock.json unless package.json dependencies change. Do not commit .env.local, node_modules, .next or generated files.
10) Preserve responsive layout, accessibility labels, loading/error/empty states and Bangladesh locale/currency assumptions (BDT, Dhaka time where applicable).
11) Before making structural changes, state the affected user flow and data flow. After changes, summarize exact files, behavior, migration/configuration needs and checks performed. Only run checks when requested by the project owner.
12) This guide describes the workspace snapshot above; re-read actual code because implementation can change after this guide is saved.
